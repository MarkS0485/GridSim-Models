# How this model was built: India transmission spine 765/400/220 kV (UnvalidatedAtScale)

These models were generated by Claude Opus 5.5 (Anthropic), working with full access to GridSim's core code base. That access is what allowed generic but detailed models to exist and to be grounded in real, published data from real operators around the world. These models are not approved for anything other than basic demonstrations. They do provide an exceptional starting point for people to expand into a much more detailed system.

General-purpose fidelity only. This is a solvable approximation for one snapshot, never planning grade, and it has not been validated against official studies (hence UnvalidatedAtScale in its name). It was assembled by a private build pipeline using GridSim's solver, from published open data only, and checked with GridSim's own power flow.

##### Area and tiling

- Bounding box (S, W, N, E): (6.5, 68.0, 35.5, 97.5), cut into 4.0 degree tiles; a tile
 the server cannot finish is split into four (recorded in acquire_state.json).
- Every statement is ANDed with the Overpass area `area["ISO3166-1"="IN"][admin_level=2]->.in;`
  (the OSM India national boundary), so only ways with a node in India arrive.

##### Queries (per tile; (S,W,N,E) substituted)

###### ehv

```
[out:json][timeout:300];area["ISO3166-1"="IN"][admin_level=2]->.in;(way["power"~"^(line|cable)$"]["voltage"~"(^|;)([2-9][0-9]{5}|[0-9]{7,})($|;)"](area.in)(S,W,N,E);way["power"~"^(line|cable)$"]["voltage"]["voltage"!~"^[0-9;]+$"](area.in)(S,W,N,E);nwr["power"~"^(substation|station|sub_station)$"](area.in)(S,W,N,E););out geom;nwr["power"="plant"](area.in)(S,W,N,E);out tags center;
```

###### hv

```
[out:json][timeout:300];area["ISO3166-1"="IN"][admin_level=2]->.in;way["power"~"^(line|cable)$"]["voltage"~"(^|;)(1[0-9]{5})($|;)"](area.in)(S,W,N,E);out geom;
```

###### stats

```
[out:json][timeout:300];area["ISO3166-1"="IN"][admin_level=2]->.in;way["power"~"^(line|cable|minor_line)$"](area.in)(S,W,N,E);convert stat ::id=id(), power=t["power"], voltage=t["voltage"], frequency=t["frequency"], line=t["line"], circuits=t["circuits"], cables=t["cables"], len_m=length();out;
```

##### Checks and what they found

- Every printed "Total of <sector>", "Total of <kV>" and "Grand Total" is compared with the sum
  of the parsed rows: 375 of 376 agree exactly. The one exception is a source error:
  tl_year_2017-03, 220 kV STATE subtotal printed 5971 ckm where its rows sum to 5917 (digits
  transposed; the 220 kV total, 6030, agrees with the rows). Any unexplained mismatch makes the
  parser raise.
- Serial numbers run 1..N in each file; a gap is recovered from the page text when the row
  fell outside the table ruling (32 substation rows recovered this way, 2 line rows had a
  blank serial cell and were inferred, each checked against the page text).
- `ss_year_2026-09.pdf`: serial 48 is absent from the PDF itself (numbering gap in the source).
- Sector headings missing in the PDF (ss 2015-03 220 kV STATE, ss 2026-03 765 kV PRIVATE, and
  others): rows take the sector named by the sector total that closes them
  (`sector_from = closing total`, 104 substation rows).
- `ss_year_2025-03.pdf` lists "220 kV Colourchem substation (1x(100-50) MVA)" twice (serials
  261 and 262, identical); both kept because the printed totals count both;
  `possible_duplicate_in_source` = True.
- One transformer ratio is printed low/high ("33/220", a hydro step-up): hv/lv swapped,
  `ratio_reversed_in_source` = True.
- The 2016-02 substations file uses fake-bold text in places ("TToottaall", "+-800 kV" garbled);
  handled.

## 3. How it was constructed and iterated

Method in brief: a snapshot build. The data the map needs was fetched once; the network was assembled (voltage classes, cuts at the borders, line and cable parameters from standard types, transformer units, plant placement, demand allocation, dispatch, slack); then solved with GridSim. Each round let the solver's findings (reactive shortfalls, overloads, angle spread, islands, fault levels) point at the next data gap. Rules held throughout: no value is changed just because it clears a solver symptom (a value adjusted to solve with no source is tagged synthetic and listed below); every value carries an evidence class (attested, derived, estimated, synthetic); a deeper, better-sourced round is kept even where it looks worse, because it exposes a real data gap; no round was ever overwritten.
